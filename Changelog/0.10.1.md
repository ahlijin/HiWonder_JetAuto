# Changelog / 更新日志

## 0.10.1 (2026-10-12)

### 修复
- **sllidar_ros2 子模块路径与目录结构同步**（`src/sllidar_ros2`）
  - 根因: 目录重构 `9fbf1d0`("修改目录结构") 把 `pi3/src` 上移为 `src/` 时, 子模块的 gitlink
    被一并删除(**没有**在新路径重新登记), 而 `.gitmodules` 仍写着 `pi3/src/sllidar_ros2`
  - 影响: 按 `.gitmodules` 拉取(clone --recurse-submodules / submodule update)得不到任何雷达驱动,
    而 `peripherals/launch/include/sllidar_a1.launch.py` 仍要启动 `sllidar_ros2` 的 `sllidar_node` →
    雷达起不来
  - 修法: 以子模块形式重新登记到 `src/sllidar_ros2`, pin 保持 `34300099`(= gitea 镜像 `legend/sllidar_ros2` main HEAD, 与重构前一致)
  - 验证: `git submodule status` 无 `-` 前缀且 pin 正确; 容器里 `colcon build` 11 个包全部编过

### 变更
- **文档同步到扁平化后的目录布局**: README.md / CLAUDE.md / doc/pi3部署.md
  - 目录树、`pi3/doc/pi3部署.md` 链接、`pi3/src/sllidar_ros2` 等旧路径全部改为 `src/` / `scripts/` / `doc/`
  - 本地 clone 路径 `/opt/data/code/...` → `/workspace/HiWonder_JetAuto`(宿主 `/home/pi/workspace/HiWonder_JetAuto`)
  - 补上 CI(推送自动编译)与开发机 my-ros 容器编译命令, 并注明两者用途区别(CI 只验证能编过, 不产出部署包)

### 注意
- 部署仍**不要**用 `--symlink-install`(symlink 指向编译机本地路径, scp 到 Pi3 后失效)
- 容器编译时 `docker -v` 必须传宿主机路径: Hermes 容器 `/workspace` = 宿主 `/home/pi/workspace`
